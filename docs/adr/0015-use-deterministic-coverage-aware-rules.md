# Use deterministic coverage-aware alert rules

The MVP will evaluate deauthentication rate, Bluetooth advertisement flooding, and identifier churn using conservative versioned thresholds normalized by actual Observed Time. Coverage Gaps pause evidence and recovery evaluation; only sufficient observed quiet time establishes recovery. Reboot marks prior active episodes interrupted and fresh qualifying evidence starts new episodes. Acknowledgment does not end an episode, and safe numeric thresholds may be overridden through documented configuration. Defaults must trigger controlled replay at their documented boundaries while a 72-hour ordinary desk soak produces zero known-false medium/high Alerts and at most three known-false low Alerts per rule. Controlled benign cases also cover roaming, intentional WiFi disconnects, sleep/wake, and ordinary BLE address changes. MVP emits Low/Medium/High only. Extreme is deferred to the release where all detections relevant to its claim are implemented and sufficient validation data supports escalation; no version is assigned, and the eventual release gate must explicitly address false Extreme Alerts. Per-rule minimum evidence, Confidence, and recovery semantics are specified in M2 before scenario expectations; numeric thresholds follow M5/M6 measurements. This rejects adaptive baselines for the MVP because learned behavior can be poisoned and is harder to explain or reproduce from retained evidence.
