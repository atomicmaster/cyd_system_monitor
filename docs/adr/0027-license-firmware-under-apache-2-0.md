# License firmware under Apache-2.0 instead of GPL-3.0-only

ADR [0025](0025-use-osi-approved-strong-copyleft-licensing.md) chose `GPL-3.0-only` for all project-authored software. Research recorded in [docs/research/gpl-esp-idf-licensing.md](../research/gpl-esp-idf-licensing.md) found that applying it to the firmware image specifically is not safe as planned: ESP-IDF's WiFi, Bluetooth-controller, and PHY radio-stack libraries (`esp32-wifi-lib`, `esp32-bt-lib`, `esp-phy-lib`) are Apache-2.0 but distributed as object code only, with no published source. GPLv3's "System Library" exception is a genuinely contestable defense for these libraries rather than a settled safe harbor, and the one real dispute over this exact category of component — a 2014 GPL compliance complaint against Espressif's own then-GPLv3 SDK — ended with Espressif abandoning GPL for that SDK rather than defending the exception. A GPL-3.0-only firmware image would put every downstream builder of this project's firmware in the same unresolvable position.

The firmware image, and any `protocol/` code compiled into it, will instead be licensed `Apache-2.0`, matching the license Espressif already uses for its own SDK and radio-stack libraries. A permissive license carries no Corresponding Source duty, so it has nothing for the object-only radio libraries to conflict with; only their copyright and attribution notices need to be preserved, which `THIRD_PARTY_NOTICES.md` already does for every dependency. This is a narrower scope change than abandoning copyleft altogether: the Rust host daemon/CLI (`host/`) and the SwiftUI setup application (`macos/setup-app/`) link against no equivalent undisclosed binary component, so they keep `GPL-3.0-only` and its protection against closed commercial derivatives where that protection costs nothing to enforce. Firmware trades that protection specifically for a coherent, enforceable license, since remaining under contested copyleft was a worse position for both the project and anyone who builds or redistributes its firmware.

Project-authored documentation remains `CC-BY-SA-4.0`, unaffected by this change.
