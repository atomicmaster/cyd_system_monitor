# TB01 — Replay a CPU snapshot into the shared display model

- **Kind:** Tracer bullet
- **Detail:** Executable
- **Status:** Awaiting hardware — desktop path and board code are complete: `./dev run simulator -- cpu-lifecycle` and `-- cpu-replay` pass, and the ESP-IDF image builds and links the same domain/UI sources (0x9c690 bytes, 69% of the smallest app partition free). Remaining: the physical run of `./dev run hardware -- cpu-replay --port "$CYD_PORT"` and its smoke record.
- **Milestones:** M2, M4
- **Depends on:** [C01](C01.md)
- **Board:** Exclusive session for final display smoke

Read [dispatch and completion rules](README.md#dispatch-and-completion) before starting. Command names below are planned deliverables, not tools that already exist.

## Outcome

A deterministic CPU snapshot passes through the production C++ decoder/domain code to a visible current value; stopped updates produce the specified stale and disconnected states on desktop and board.

## Ownership and inputs

Own `firmware/domain/host-state/`, `firmware/ui/system/cpu/`, the initial status/display shell, and CPU scenarios under `simulator/scenarios/`. Consume C01 types and F02 renderer targets. The simulator supplies fake transport/time through the same interfaces used by firmware; Rust does not implement a second display-state machine.

## Work

1. Add explicit clock and snapshot-input interfaces with source ages, availability, last-seen state, and cold-boot unknown time.
2. Render one CPU card plus minimal persistent connection/clock status. Provide a board replay adapter so physical display checks do not require the later Mac collector.
3. Replay first unavailable rate, valid rate, all availability states, delayed/stale input, recovery, time correction, and malformed/stale-session rejection.

## Acceptance

- At three seconds without snapshots, the value dims and is labeled `Last`; animation decays without claiming measured zero. At 15 seconds, connection status is disconnected.
- A fresh complete snapshot restores live state; old source timestamps remain old even if a snapshot arrives now.
- Cold boot shows `Time unavailable`; time correction preserves existing evidence ordering.
- Desktop and ESP32 link the same domain source. Board replay visibly matches the fixture and preserves calibration/navigation.
- UI extension points are recorded for C02; this ticket does not build all six cards or historical graphs.

## Verification and handoff

Run `./dev check firmware`, `./dev check simulator`, `./dev run simulator -- cpu-lifecycle`, and `./dev run hardware -- cpu-replay --port "$CYD_PORT"`. Retain deterministic expected states and desktop visual fixtures plus a physical smoke record. Hand off the rendering/input/clock interfaces and the integrated commit to TB02.

## Progress and handoff notes

- **Interfaces (shared by desktop and board):** `firmware::domain::MonotonicClock` (scripted in the simulator, `esp_timer` on the board), `HostFeed` (bytes → `FrameStream` → decode → session gate → reducer; `Tick()` also advances staleness and abandons a partial frame idle for 250 ms), `MakeCpuView(HostState, now)` (all display text and flags), and `firmware::ui::system::CpuScreen::Update(view)`.
- **Behavior covered by the scenario transcript:** cold boot `Time unavailable`; unavailable/unsupported/absent/error show no value (never `0%`); dim and `Last` at 3 s, Disconnected at 15 s with the value retained; recovery restores live; source time is receipt time minus reported age; UTC correction changes only the displayed clock; stale-sequence, wrong-session, bad-CRC and incompatible-major input is rejected; fragmented delivery; reconnect with a fresh session.
- **Codec change:** `FrameStream::DropLeadingByte()` (C++ and Rust) lets the adapter recover promptly from a false length; documented in `protocol/CORE_PROTOCOL.md`.
- **C02 extension points:** further cards follow `Update(view)` beside `CpuScreen` with a pure `Make<X>View(HostState, now)`; `HostFeed`/`HostState` gain one field group per metric; the status bar is currently owned by `CpuScreen` and should be split out when a second card arrives.
- **Board replay:** `DEV:CPU_REPLAY` (dev console) asks the `app_main` loop to draw `firmware::domain::CpuReplay`'s scripted timeline on `CpuScreen`, logging one `cpu-replay: <checkpoint>` line per checkpoint, then returns to the diagnostic screen so calibration and touch navigation are untouched. `./dev run hardware -- cpu-replay --port P` flashes, sends the command, and diffs the board log against `simulator/scenarios/cpu-replay.expected` (the desktop transcript of the same script); `tools/hardware/cpu_replay_capture.py` needs the IDF Python environment for pyserial and a calibrated board.
- **Build finding:** the GCC `-Werror` ESP-IDF build rejected two warnings clang accepted in the C++ codec; fixed, and the protocol lane now compiles the codec with `-Wall -Wextra -Werror`.
- **Not done here:** the physical run and its smoke record; the desktop visual fixture is a text transcript because the simulator is headless (no rendered image).
