# TB01 — Replay a CPU snapshot into the shared display model

- **Kind:** Tracer bullet
- **Detail:** Executable
- **Status:** Not started
- **Milestones:** M2, M4
- **Depends on:** [C01](C01.md)
- **Board:** Exclusive session for final display smoke

Read [dispatch and completion rules](README.md#dispatch-and-completion) before starting. Command names below are planned deliverables, not tools that already exist.

## Outcome

A deterministic CPU snapshot passes through the production C++ decoder/domain code to a visible current value; stopped updates produce the specified stale and disconnected states on desktop and board.

## Ownership and inputs

Own `firmware/domain/host-state/`, `firmware/ui/system/cpu/`, the initial status/display shell, and CPU scenarios under `simulator/scenarios/`. Consume C01 types and F02 renderer targets. The simulator supplies fake transport/time through the same interfaces used by firmware; Rust does not implement a second display-state machine.

## Work

1. Add explicit clock and snapshot-input interfaces with source ages, availability, last-seen state, and cold-boot unknown time.
2. Render one CPU card plus minimal persistent connection/clock status. Provide a board replay adapter so physical display checks do not require the later Mac collector.
3. Replay first unavailable rate, valid rate, all availability states, delayed/stale input, recovery, time correction, and malformed/stale-session rejection.

## Acceptance

- At three seconds without snapshots, the value dims and is labeled `Last`; animation decays without claiming measured zero. At 15 seconds, connection status is disconnected.
- A fresh complete snapshot restores live state; old source timestamps remain old even if a snapshot arrives now.
- Cold boot shows `Time unavailable`; time correction preserves existing evidence ordering.
- Desktop and ESP32 link the same domain source. Board replay visibly matches the fixture and preserves calibration/navigation.
- UI extension points are recorded for C02; this ticket does not build all six cards or historical graphs.

## Verification and handoff

Run `./dev check firmware`, `./dev check simulator`, `./dev run simulator -- cpu-lifecycle`, and `./dev run hardware -- cpu-replay --port "$CYD_PORT"`. Retain deterministic expected states and desktop visual fixtures plus a physical smoke record. Hand off the rendering/input/clock interfaces and the integrated commit to TB02.
