# C02 — Publish the extension interfaces for parallel feature slices

- **Kind:** Contract foundation
- **Detail:** Outline
- **Status:** Not started
- **Milestones:** M2
- **Depends on:** [TB02](TB02.md)
- **Board:** None

Read [dispatch and completion rules](README.md#dispatch-and-completion). Refine this outline against prerequisite evidence before dispatch; it is not yet executable.

## Outcome

Feature agents can add collectors, views, and radio adapters without each redesigning snapshots, shared state, or the application entrypoint.

## Proposed ownership

Own shared schema/type changes, `firmware/domain/` public interfaces, Host collector interfaces, UI composition points, and replay fixture conventions. Consumers own per-feature implementations. Generated outputs are changed only through their schema sources.

## Scope

Define the next required metric fields/units/ages, collection-result interface, card/detail inputs, radio observation/coverage events, bounded episode evidence, configuration revision semantics, and persistence adapter operations. Use the actual CPU path to keep interfaces small. Give firmware and desktop replay concrete adapters; share C++ domain source rather than implementing rules in Rust. Specify per-feature registration files so parallel tickets do not all edit one switch statement.

## Resolve before promotion

Use F08 budgets and TB02 message measurements to set bounds. Select only interfaces needed by the listed MVP consumers. Document ownership/threading, ordering, errors, enablement/freshness distinctions, clock/boot identity, unknown-field compatibility, and traceable fixture examples. Each rule owner must document minimum-evidence, Confidence, and recovery semantics before its scenario expectations are fixed; C02 need not implement all rules.

## Acceptance outline

- Existing CPU pairing/reconnect replay remains unchanged through the interfaces.
- C++/Rust contract fixtures agree; representative maximum messages fit measured limits.
- Two distinct consumers can use each new extensibility mechanism; identify exact module paths and shared-file edit exclusions for parallel dispatch.
- Configuration retry/revision and journal commit/recovery expectations are explicit enough for TB13/TB16 to refine independently of collectors.

## Verification to specify

Use protocol, Host, firmware, and simulator checks, including CPU regression and cross-runtime contract fixtures. Record exact fixture/scenario names, commands, and evidence paths when promoting this ticket.
