# C02 — Publish the extension interfaces for parallel feature slices

- **Kind:** Contract foundation
- **Detail:** Executable
- **Status:** Done — metric-group wire extension (RAM as the stub), card registry, Host collector trait, and the written radio/episode/config/persistence contracts; see Handoff.
- **Milestones:** M2
- **Depends on:** [TB02](TB02.md)
- **Board:** None

Read [dispatch and completion rules](README.md#dispatch-and-completion).

## Outcome

Feature agents can add collectors, views, and radio adapters without each redesigning snapshots, shared state, or the application entrypoint.

## Proposed ownership

Own shared schema/type changes, `firmware/domain/` public interfaces, Host collector interfaces, UI composition points, and replay fixture conventions. Consumers own per-feature implementations. Generated outputs are changed only through their schema sources.

## Scope

Define the next required metric fields/units/ages, collection-result interface, card/detail inputs, radio observation/coverage events, bounded episode evidence, configuration revision semantics, and persistence adapter operations. Use the actual CPU path to keep interfaces small. Give firmware and desktop replay concrete adapters; share C++ domain source rather than implementing rules in Rust. Specify per-feature registration files so parallel tickets do not all edit one switch statement.

## Resolve before promotion

Use F08 budgets and TB02 message measurements to set bounds. Select only interfaces needed by the listed MVP consumers. Document ownership/threading, ordering, errors, enablement/freshness distinctions, clock/boot identity, unknown-field compatibility, and traceable fixture examples. Each rule owner must document minimum-evidence, Confidence, and recovery semantics before its scenario expectations are fixed; C02 need not implement all rules.

## Acceptance outline

- Existing CPU pairing/reconnect replay remains unchanged through the interfaces.
- C++/Rust contract fixtures agree; representative maximum messages fit measured limits.
- Two distinct consumers can use each new extensibility mechanism; identify exact module paths and shared-file edit exclusions for parallel dispatch.
- Configuration retry/revision and journal commit/recovery expectations are explicit enough for TB13/TB16 to refine independently of collectors.

## Verification to specify

Use protocol, Host, firmware, and simulator checks, including CPU regression and cross-runtime contract fixtures. Record exact fixture/scenario names, commands, and evidence paths when promoting this ticket.

## Decisions (agreed before implementation)

- **Wire:** additive groups at snapshot-body keys ≥ 5; CPU keys 0–4 unchanged, so the CPU replay and old fixtures stay valid and the protocol stays 1.x.
- **Registration:** one `CYD_CARD` line per feature in `card_registry.def`, per-feature files elsewhere.
- **Scope:** metric path plus one stub group (RAM); radio, episode, configuration, and persistence interfaces are written contracts and fixtures only.

## Handoff

- **Contract doc:** [Extension interfaces](../extension-interfaces.md) (adding a metric, exclusive files and the single shared line per step, bounds, threading) and the "Metric groups" section of `protocol/CORE_PROTOCOL.md`.
- **Wire/codecs:** `RamSnapshot`/`EncodeSnapshot` in `protocol/core/cpp/protocol.*`; `RamSnapshot`, `Snapshot`, `encode_snapshot`, `decode_snapshot` in `host/protocol/src/lib.rs`. 14 RAM fixtures (`protocol/fixtures/ram-snapshot-v1*.hex`) with rows in `parity-matrix.txt`; the parity gate now compares RAM fields and re-encoded bytes (229,703 inputs, 0 mismatches).
- **Parity finding:** Rust once counted skip depth from the group map instead of from the unknown value; found by the gate, fixture `ram-snapshot-v1-unknown-nested.hex` added, envelope skipping made group-aware.
- **Device:** `HostState.ram` (own 3 s freshness), `firmware/domain/card_registry.{hpp,def}` + `src/cards/{cpu,ram}_card.cpp`. The CPU card is exactly the `CpuView` value path.
- **Host:** `metrics::Collector`, `ScriptedCollector`, `RamReading`; `platform_macos::cpu::CpuCollector` (used by `cyd-host run`); `HostClient::snapshot` takes optional groups.
- **Replay/fixtures:** simulator scenario `metric-cards` (`simulator/scenarios/metric-cards.expected`); `link_parity.rs` proves a RAM group reaches the C++ `HostLink` state.
- **Two consumers per mechanism:** groups: CPU and RAM; cards: CPU and RAM; collectors: CPU (real) and scripted RAM (fixture).
- **Not done:** a generic LVGL card widget (TB03 adds the first real second card on the display), a real macOS RAM collector (TB03), and any implementation of the radio/episode/config/persistence contracts. The RAM group is not sent by `cyd-host` yet.
- **Shared-file exclusions for parallel dispatch:** protocol codec files and `HostState` are serial (one metric at a time, behind the parity gate); everything else per the table in the contract doc.
