- **Kind:** Tracer bullet
- **Detail:** Executable
- **Status:** Awaiting hardware — the Agents wire group, both codecs, the pure allowlist classifier, the macOS libproc collector, the Agents bar (formerly a card), and the simulator scenario are implemented and pass on the desktop (working tree, not yet committed). - **Milestones:** M3, M4
- **Depends on:** [C02](C02.md)
- **Board:** Exclusive final display smoke; an installed agent optional

Read [dispatch and completion rules](README.md#dispatch-and-completion).

## Outcome

The Agents bar distinguishes supported same-user process presence from no process and from an unavailable source, with activity unknown unless an accepted source supports more.

## Design (as built)

- **Wire:** group key 8 "Agents" in [CORE_PROTOCOL.md](../../protocol/CORE_PROTOCOL.md#metric-groups-c02), five required fields: availability (0-4, of the process listing as a whole), source age (ms, 32-bit), then three fixed slots in the order Codex, Claude, Grok Build, each a state (0 not running, 1 running with activity unknown, 2 busy, 3 idle). MVP Hosts send only 0 and 1; 2 and 3 need an activity adapter that does not exist yet, and are accepted and labelled by both codecs and the card. When availability is not Available every state is 0 and the card shows `--`, never "None running". No freshness field. A per-agent process count was left out (no display use). Largest group 16 bytes (limit 64).
- **Host pure classifier:** `host/metrics/src/agents.rs`. `classify(records, uid, home)` takes only `(uid, resolved path)` records and matches them exactly against the `ALLOWLIST` table (version-numbered directories via a strict semver segment, bundle roots only inside `<bundle>/Contents/`). Every entry and its reasoning: [agent integrations](../agent-integrations.md#process-presence-what-counts-as-a-supported-agent-tb07).
- **Host collector:** `host/platform-macos/src/agents.rs` (`proc_listallpids`, `proc_pidinfo` for the uid only, `proc_pidpath`, `realpath`; no dependency). At most 4,096 pids and 100 ms per scan, run inline on `collect` every 5 s (measured 6-17 ms), cached in between with its own age. An exited process is skipped; a failed scan keeps the last sample with its growing age for 15 s and then reports Error; with no sample yet it is TemporarilyUnavailable until scans have failed for 15 s, then Error. A failed scan is retried at the same 5 s cadence. `link.rs`: `agents_snapshot`.
- **Device:** `AgentsMetricState`. Stale 15 s after the source sample (5 s cadence x3), derived from the reported age with a signed source time, so a re-sent old sample or one older than the device's uptime is not fresh.
- **Card:** `Agents`, value `None running` / `1 running` (`Last ` prefix when retained), note the activity known: `Claude, unknown` for one agent without an adapter, `Activity unknown` for several, `Claude busy` / `Grok idle` / `1 busy 1 idle 1 unknown` for a future adapter. `--` plus `Unavailable` or `Read error` otherwise. No bar: `MetricCardView` gained `show_bar` (default true) because Agents has a value that is not a proportion.

## Acceptance

- Same-named unrelated binaries, other-user processes, and Homebrew's `grok` never count: `a_same_named_unrelated_binary_never_counts`, `another_users_process_on_an_allowlisted_path_does_not_count`, `homebrew_grok_is_not_grok_build`.
- Relative, empty, `..`, unnormalised, and over-long (over 1,024 bytes) paths are rejected: `malformed_relative_and_overlong_paths_are_rejected`; bundle helpers count only inside the bundle root: `bundle_helpers_count_only_inside_the_bundle_root`; symlinks are resolved before matching: `a_symlink_already_resolved_into_the_allowlist_matches_only_when_resolved`; duplicates count once; zero processes is all not running.
- Process-exit races skip that pid; a listing failure is `TemporarilyUnavailable` (then `Error`), never not-running: `a_listing_failure_is_unavailable_never_not_running`, `scans_failing_from_startup_become_an_error_after_15_s_at_the_normal_cadence`, `a_failed_refresh_retains_the_old_sample_then_reports_an_error`, simulator steps `process listing temporarily unavailable` and `process listing error`.
- Running without an activity source reads activity unknown, never busy or idle: `presence_never_yields_busy_or_idle`, simulator steps `Claude running, no activity source` and `Codex and Claude running`. Busy and idle labelling is proven through the wire fixtures `agents-snapshot-v1-busy-idle.hex` and the `future adapter` steps.
- Collection never reads arguments, environment, cwd, open files, prompts, conversations, or credentials: by construction (`ProcessRecord` carries only uid and path; `proc_pidinfo` is read for the uid only) and stated in the agent integrations table.
- Availability, freshness, and adapter enablement stay distinct: freshness from the source age (`test_host_state.cpp` blocks 50-55, simulator steps around 15 s), availability on its own field, no adapter exists.
- C++ and Rust codecs agree on every `agents-*` row of `parity-matrix.txt` (0 mismatches); link parity `an_agents_group_reaches_the_firmware_state_and_unavailable_is_not_none_running`.
- Every Agents value and note variant (all 64 state combinations, fresh and `Last`, each unavailable wording) fits 148 px: `system-screen` measures them on a real card widget (widest value 135 px, widest note 134 px).
