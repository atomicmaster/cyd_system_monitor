# F01 — Establish repository ownership and developer entrypoints

- **Kind:** Foundation
- **Detail:** Executable
- **Status:** Not started
- **Milestones:** M0
- **Depends on:** None
- **Board:** None

Read [dispatch and completion rules](README.md#dispatch-and-completion) before starting. Command names below are planned deliverables, not tools that already exist.

## Outcome

Each runtime has a reserved home and a predictable developer command, allowing the firmware and Host toolchain tickets to proceed independently.

## Ownership and inputs

Own root `dev`, root tool configuration/ignore rules, `tools/dev/` dispatch conventions, and `docs/development.md`. Preserve the existing planning and license files. Reserve `firmware/`, `host/`, `macos/setup-app/`, `protocol/`, and `simulator/` according to [repository layout](../repository-layout.md). F02 and F03 own their runtime build files.

## Work

1. Define `./dev help`, `./dev doctor`, and `./dev {build,check,run} <target> [-- arguments]`. Use a small dispatcher into separately owned target scripts under `tools/dev/`; unsupported or unfinished targets fail clearly rather than returning success.
2. Document environment prerequisites and target-script exit codes. Keep developer dependency fetching distinct from the installed product's outbound-traffic restriction.
3. Record the initial ownership map and generated-file convention. Runtime pins are provided by F02/F03; schema-generation pins are completed by F04. The hardware profile remains the pin/capability source of truth.

## Acceptance

- A fresh checkout explains which prerequisites exist and which remain to be installed; the help command works before runtime toolchains are installed.
- Commands preserve argument boundaries, propagate failures, and do not silently install privileged software, flash a board, or start a long hardware run.
- F02 and F03 can add their target scripts without both editing the root dispatcher.
- Source-license defaults follow [CONTRIBUTING.md](../../CONTRIBUTING.md); documentation does not depend on ignored vendor downloads.

## Verification and handoff

Run `./dev help` and `./dev doctor`; record expected missing-tool results. Exercise one failing/unknown target and show its nonzero result. Hand off the command grammar, reserved paths, and exact base commit to F02/F03. This ticket does not claim that M0 builds pass yet.
