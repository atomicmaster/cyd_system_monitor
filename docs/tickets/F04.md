# F04 — Integrate reproducible builds and CI

- **Kind:** Integration gate
- **Detail:** Executable
- **Status:** Not started
- **Milestones:** M0
- **Depends on:** [F02](F02.md), [F03](F03.md)
- **Board:** None

Read [dispatch and completion rules](README.md#dispatch-and-completion) before starting. Command names below are planned deliverables, not tools that already exist.

## Outcome

One clean-checkout command verifies all runnable skeletons, establishing a common base for hardware work and subsequent agents.

## Ownership and inputs

Own `.github/workflows/`, `tools/dev/{all,protocol}.sh`, `protocol/` generator bootstrap, combined toolchain documentation, and dependency-notice aggregation. Runtime build files remain with their lane owners; coordinate needed fixes instead of replacing their work.

## Work

1. Choose and pin the language-neutral schema/generation tooling with a minimal generation smoke fixture and both C++/Rust consumers. C01 defines the first product messages; this smoke fixture is not the product contract.
2. Add CI for firmware, Rust, Swift, desktop/native checks, formatting, and schema regeneration checks. Choose supported runners explicitly and expose signing or desktop-display constraints.
3. Integrate build/check targets and document a clean Apple Silicon macOS 26 bootstrap independent of vendor caches.

## Acceptance

- `./dev check all` executes every available lane, fails on a failing lane, and does not silently skip a required runtime.
- Generated smoke outputs are reproducible and checked for drift; CI produces actionable failures and records pins.
- A clean-environment build is demonstrated, or its missing evidence is recorded and this gate remains open. Local success alone is not a clean-machine claim.
- M0 exit criteria in the [plan](../../IMPLEMENTATION_PLAN.md) are mapped to recorded evidence.

## Verification and handoff

Run `./dev build firmware`, `./dev build host`, `./dev build macos`, `./dev build simulator`, `./dev check protocol`, and `./dev check all`. Record CI links or retained logs and the integrated base commit. Only a passed gate enables F05.
