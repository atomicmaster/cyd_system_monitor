# F02 — Build firmware and desktop targets from one C++ core

- **Kind:** Foundation
- **Detail:** Executable
- **Status:** Not started
- **Milestones:** M0
- **Depends on:** [F01](F01.md)
- **Board:** None

Read [dispatch and completion rules](README.md#dispatch-and-completion) before starting. Command names below are planned deliverables, not tools that already exist.

## Outcome

A pinned ESP-IDF/LVGL toolchain builds an empty E32R28T application and a desktop LVGL target that can share firmware domain code.

## Ownership and inputs

Own `firmware/` build scaffolding, `simulator/` desktop build scaffolding, C++ formatting configuration scoped to those trees, and `tools/dev/{firmware,simulator}.sh`. Read the [hardware profile](../../hardware/profiles/lcdwiki-esp32-32e-2.8/README.md). F03 owns Rust/Swift files; F04 owns shared CI and protocol tooling.

## Work

1. Pin compatible ESP-IDF, LVGL, compiler/build, and desktop-rendering dependencies; document deterministic bootstrap and dependency notices.
2. Separate `firmware/domain/`, `firmware/platform/esp32/`, and `firmware/ui/`. Link the same domain source target into the ESP32 and desktop builds; keep ESP-IDF headers out of the domain interface.
3. Build a minimal desktop window and firmware image. Validate profile fields at build time without copying pin constants into application modules.
4. Supply developer build/check/run targets and report image size. Physical display drivers belong to F05.

## Acceptance

- Both builds succeed on supported Apple Silicon macOS without ignored vendor archives.
- A desktop smoke scenario can run with a controllable clock; there is no second copy of domain behavior in Rust or simulator-only code.
- Unsupported profile values fail clearly; the active profile produces 320×240 landscape geometry.
- A trivial native domain test proves the target is usable independently of ESP-IDF; it does not pretend to validate radio or display performance.

## Verification and handoff

Run `./dev build firmware`, `./dev build simulator`, `./dev check firmware`, `./dev check simulator`, and `./dev run simulator -- smoke`. Provide build identities, pins, image-size output, and the domain/renderer target names. F04 integrates these commands into CI; F05 begins physical bring-up after M0 integration.
