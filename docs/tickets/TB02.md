# TB02 — Pair a Mac and display live CPU over USB

- **Kind:** Tracer bullet
- **Detail:** Executable
- **Status:** Done — a paired Mac supplies live CPU to the physical display; see the Handoff and Physical smoke record below.
- **Milestones:** M2, M3, M4
- **Depends on:** [TB01](TB01.md)
- **Board:** Exclusive E32R28T session

Read [dispatch and completion rules](README.md#dispatch-and-completion) before starting. Command names below are planned deliverables, not tools that already exist.

## Outcome

A paired Mac supplies real CPU usage through CBOR/USB to the physical display. Stopping the producer dims the last value; restarting or reconnecting establishes a new session and restores live state.

## Ownership and inputs

One slice owner integrates `host/crates/metrics-macos/cpu`, Host USB/session/CLI modules, `firmware/platform/esp32/usb`, pairing identity storage, and the minimal pairing/About UI. Consume C01 codec and TB01 display-state interfaces; coordinate shared-contract changes with C01's owner. A foreground producer is sufficient here; LaunchAgent and SwiftUI lifecycle belong to TB08.

## Work

1. Implement Mach CPU tick deltas using monotonic elapsed samples, preserving first-sample and reset unavailability.
2. Discover/enumerate compatible monitors, display a matching short code, require touch confirmation, and persist one-to-one identities before exchanging Host Metrics. Make unpairing explicit and preserve retained state.
3. Negotiate versions/capabilities/revisions/time, send an immediate complete snapshot followed by complete one-second snapshots, and reject old-session data/command retries appropriately.
4. Replace F06's development recovery command with the bounded negotiated calibration-reset command. Preserve a usable recovery path for broken touch without implying cryptographic pairing.
5. Expose incoming/supported/negotiated versions and visible incompatibility cause in minimal About/diagnostics. Later tickets connect these faults to the full Operational Alert model.

## Acceptance

- Real CPU values reach the board only after pairing; simulated additional devices do not receive Host data.
- Restart, powered data-link loss, unplug/power loss, and sleep/wake produce distinct correct transitions; resumed rates begin unavailable until a valid baseline exists.
- Stale/disconnected timing follows TB01 and source age remains truthful. Radio feasibility support is preserved, but production standalone radio acceptance belongs to TB09 onward.
- Protocol mismatch is visible, rejects Host data/configuration, and leaves device diagnostics usable.
- Actual message size/rate remains within F08/C01 budgets. The integrated demonstration uses no root helper or background network client.

## Verification and handoff

Run `./dev check all`, `./dev run simulator -- cpu-lifecycle`, and `./dev run hardware -- paired-cpu --port "$CYD_PORT"`. Supply a reproducible Host start/stop recipe and operator steps for pairing, sleep/wake, unplug, and recovery. Record real-board evidence and the shared base commit. The first working path is complete; C02 can now define the small extension contracts needed for parallel feature slices.

## Handoff

- **Contract:** `protocol/CORE_PROTOCOL.md` "Link handshake and pairing" — `CYD:LINK` text line switches UART0 from the ASCII console to frames; Hello → HelloReply → Pair (touch confirmation on first pairing) → snapshots at 1 Hz in a fresh Host-chosen session; Error body byte 1 incompatible, 2 not paired with you, 3 declined/timeout, 4 bad request. Commands: unpair, calibration reset (idempotent by identity).
- **Device:** `firmware/domain` `HostLink` (state machine), `link_view` (About/prompt text), `HostFeed` explicit-session gate; `firmware/platform/esp32/usb` (link mode), `nvs/pairing_store`; `firmware/ui/system/link` `LinkScreen`; wiring in `firmware/main/main.cpp` (`PumpLink`). `DEV:UNPAIR` remains as a development recovery for a lost Mac; `DEV:CLEAR_CALIBRATION` is unchanged (F06's recovery), and `reset-calibration` is the negotiated replacement.
- **Host:** `metrics::CpuSampler`, `platform-macos::cpu`, `transport::client` (state machine) and `transport::serial`, `cli` (`cyd-host run|unpair|reset-calibration|forget`). Identity file: `$CYD_HOME` or `~/.cyd-host/identity`.
- **Parity gate for the link:** `host/transport/tests/link_parity.rs` drives the Rust client against the real C++ `HostLink` (`firmware/domain/tests/link_cli`, built by `./dev check host`). No codec bytes changed, so the codec parity corpus is unchanged (179,932 inputs, 0 mismatches).
- **Reproducible recipe:** `./dev run hardware -- paired-cpu --port /dev/cu.usbserial-140` flashes and starts the producer; or `cd host && cargo run --bin cyd-host -- run --port <port>`. Ctrl-C stops the producer. Opening the port resets the ESP32, so the Host waits 3 s before talking.
- **Operator steps:** (1) Pairing: run, read the code the Host prints, tap Confirm on the display within 60 s. (2) Stop/restart: Ctrl-C then run again; reconnect needs no touch. (3) Unplug: unplug and replug while running; the Host logs `link lost` and reconnects on a new session. (4) Sleep/wake: the USB serial device drops during sleep; the Host reconnects on wake and the first sample is unavailable. (5) Recovery: `cyd-host unpair` (from the paired Mac), `cyd-host reset-calibration`, `cyd-host forget` (Mac side only), `DEV:UNPAIR` over the console if the Mac is lost.
- **Known limits:** the link is foreground only (LaunchAgent belongs to TB08); link mode ends only on board reset; device logs are silenced in link mode; the board's polling UART needs the reader task to run every ≤10 ms, which holds at these frame sizes (about 61 bytes per snapshot at 1 Hz). The incoming major of an unsupported-major frame is not decoded, so About shows the major only when a Hello body decodes (a Hello with an incompatible body major shows it).
- **Shared base commit:** the commit that marks TB02 done (see `git log`).

## Physical smoke record

Board ESP32-D0WD-V3 on `/dev/cu.usbserial-140`, Mac host, CYD_HOME isolated.

- First pairing: prompt with code appeared, Confirm accepted; CPU showed live values matching the Host (about 8%); first sample unavailable, then real. Status bar live, About showed Supported 1.0 / Host 1.0 / Negotiated 1.0 / Paired.
- Producer stopped: value dimmed and showed `Last` (stale), then Disconnected.
- Producer restarted: reconnected without touch on a new session; live again.
- Unplug/replug while running: Host logged `link lost` (Device not configured, then No such file), retried every 2 s, re-paired without touch when the port returned; display recovered.
- Sleep/wake (Mac plugged in and on battery): display Stale then Disconnected during sleep; USB serial dropped and the Host reconnected on wake; first post-wake sample was unavailable, then live.
- `cyd-host unpair`: applied; the next `run` showed the pairing prompt again and needed a touch (the board had forgotten the Mac).
- `cyd-host reset-calibration`: applied; the board restarted into guided calibration and recalibrated normally.
- Protocol mismatch: a Hello with body major 2 was answered with Error(1); the display showed `Host: 2.0` and "Incompatible protocol: Host data rejected" in red; no Host data applied. Not exercised on hardware: a simulated second Host device (covered by `a_second_host_is_refused_by_a_paired_device`).
- Size/rate: about 61 bytes per snapshot at 1 Hz, within the 2,048-byte frame limit.
- Checks: `./dev check all` passes (protocol, host, firmware, simulator).
