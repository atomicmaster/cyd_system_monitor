# TB02 — Pair a Mac and display live CPU over USB

- **Kind:** Tracer bullet
- **Detail:** Executable
- **Status:** Not started
- **Milestones:** M2, M3, M4
- **Depends on:** [TB01](TB01.md)
- **Board:** Exclusive E32R28T session

Read [dispatch and completion rules](README.md#dispatch-and-completion) before starting. Command names below are planned deliverables, not tools that already exist.

## Outcome

A paired Mac supplies real CPU usage through CBOR/USB to the physical display. Stopping the producer dims the last value; restarting or reconnecting establishes a new session and restores live state.

## Ownership and inputs

One slice owner integrates `host/crates/metrics-macos/cpu`, Host USB/session/CLI modules, `firmware/platform/esp32/usb`, pairing identity storage, and the minimal pairing/About UI. Consume C01 codec and TB01 display-state interfaces; coordinate shared-contract changes with C01's owner. A foreground producer is sufficient here; LaunchAgent and SwiftUI lifecycle belong to TB08.

## Work

1. Implement Mach CPU tick deltas using monotonic elapsed samples, preserving first-sample and reset unavailability.
2. Discover/enumerate compatible monitors, display a matching short code, require touch confirmation, and persist one-to-one identities before exchanging Host Metrics. Make unpairing explicit and preserve retained state.
3. Negotiate versions/capabilities/revisions/time, send an immediate complete snapshot followed by complete one-second snapshots, and reject old-session data/command retries appropriately.
4. Replace F06's development recovery command with the bounded negotiated calibration-reset command. Preserve a usable recovery path for broken touch without implying cryptographic pairing.
5. Expose incoming/supported/negotiated versions and visible incompatibility cause in minimal About/diagnostics. Later tickets connect these faults to the full Operational Alert model.

## Acceptance

- Real CPU values reach the board only after pairing; simulated additional devices do not receive Host data.
- Restart, powered data-link loss, unplug/power loss, and sleep/wake produce distinct correct transitions; resumed rates begin unavailable until a valid baseline exists.
- Stale/disconnected timing follows TB01 and source age remains truthful. Radio feasibility support is preserved, but production standalone radio acceptance belongs to TB09 onward.
- Protocol mismatch is visible, rejects Host data/configuration, and leaves device diagnostics usable.
- Actual message size/rate remains within F08/C01 budgets. The integrated demonstration uses no root helper or background network client.

## Verification and handoff

Run `./dev check all`, `./dev run simulator -- cpu-lifecycle`, and `./dev run hardware -- paired-cpu --port "$CYD_PORT"`. Supply a reproducible Host start/stop recipe and operator steps for pairing, sleep/wake, unplug, and recovery. Record real-board evidence and the shared base commit. The first working path is complete; C02 can now define the small extension contracts needed for parallel feature slices.
