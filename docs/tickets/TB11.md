## Outcome

## Promotion decisions and metadata

TB11 owns `firmware/platform/esp32/radio/ble_scanner.*`, `firmware/domain/include/firmware/domain/hci/hci.hpp` and its parser, `firmware/domain/include/firmware/domain/ble_observation.hpp`, `firmware/domain/src/ble_observation.cpp`, `firmware/ui/include/firmware/ui/ble_screen.hpp`, `firmware/ui/src/ble_screen.cpp`, `simulator/fixtures/ble_observation.hpp`, `simulator/scenarios/ble_observation.cpp` and `simulator/scenarios/ble-observation.expected`. Coordinate the shared handoff and event representation with TB10 and serialize build/navigation registration with the integration owner.

Legacy LE Set Scan Enable supplies legacy reports only; extended advertising is excluded and is future scope. Count complete connectable undirected, connectable directed, scannable undirected and non-connectable undirected reports, without controller duplicate filtering. Scan responses and Classic Bluetooth are excluded. Every repeat counts for TB14; if filtering cannot be disabled, the rule is unevaluable, not quiet. Addresses identify Observed Transmitters, not physical objects; Signal Strength is not distance.

The fixed BLE event contains protocol, window ID and configuration generation (`u32`), arrival monotonic microseconds (`u64`), legacy advertising type (`u8`), six-byte address and public/random type, random subtype, RSSI (`i8` dBm plus validity), data length (`u8`, 0–31), optional flags (`u8`), optional manufacturer company ID (`u16`), and up to four UUIDs (each width and 16-byte value), plus presence, malformed and overflow flags. Four UUID slots need at least 68 bytes. Key transmitters by `(address type, address)`; identical public and random bytes remain distinct. HCI addresses are little-endian: only for random addresses decode `address[5] >> 6`: 00 non-resolvable private, 01 resolvable private, 10 reserved, 11 static. Reserved remains visible but is ineligible for churn; public is never decoded as random. HCI RSSI 127 is unavailable; sort unavailable last, never use it as a numeric measurement.

On the HCI worker, parse `hci::Report::data` while its temporary packet storage remains valid, before `BleScanner::OnReport` returns; copy only decoded fields into the event. Parse AD length and type within the 31-byte legacy limit; a zero length terminates the AD list and trailing bytes are ignored. A complete directed report with zero data is valid. A truncated HCI report is rejected entirely; a complete report with malformed optional AD is marked malformed and is also ineligible for both flood and churn, consistent with [alert rules §3.1 and §4.1](../alert-rules.md). Count either rejection separately. More than four complete UUIDs sets overflow and retains the first four in wire order; the complete report remains eligible for flood/churn, but its decoded list is explicitly incomplete. Never retain raw AD bytes or payload. Raw addresses may be retained locally under ADR 0007; escape any derived labels at render time into a bounded 129-byte buffer.

Recognize only these bounded signatures, with lengths measured in AD value bytes after the type byte:

| Label | Signature and minimum | Retained fields |
| --- | --- | --- |
| iBeacon | Manufacturer AD, Apple company ID `0x004c`, `02 15`, at least 25 bytes total including company ID | UUID 16 bytes, major/minor u16, measured power i8 |
| Eddystone | Service Data 16-bit UUID `0xfeaa`, at least 3 bytes including UUID and frame type | frame type; decode UID only with at least 20 bytes, URL only with at least 4, TLM only with at least 16; otherwise label incomplete, retain no frame body |
| Find My-pattern | Manufacturer AD, Apple company ID `0x004c`, type `0x12`, subtype length byte present, at least 4 bytes total and declared subtype length fits | pattern label and subtype length only |

Near matches (wrong company, type, UUID, prefix or short length) do not receive the corresponding label. Find My-pattern is an untrusted format label, not an AirTag, tracker or physical-identity claim. No decoded label is a rule confidence input.

## Handoff, resources and view

Use TB10's [shared radio handoff contract](TB10.md#shared-radio-handoff-contract-tb10-owner), combined memory worksheet and three separately measured CPU ceilings. HCI extraction runs on the HCI worker; aggregation runs on the radio task after draining. TB10's consumer supplies accepted events and per-window reports to TB14/15 in sequence order. Missing reports and gaps yield no eligible evidence; eligible dropped or uncertain windows supply lower-bound counts but never observed quiet. VHCI packet loss is not a report count; late processing and unassignable loss must make the relevant window uncertain. TB15 owns its separate candidate 256-entry known-set and baseline-admission logic; TB11's display table has 128 entries, least-recently-seen eviction with address/type tie-break, saturated counters and visible eviction count.

From Overview add a BLE entry; Back returns to Overview, detail Back returns to the list. The app loop owns immutable snapshot copies refreshed at 1 Hz regardless of Host connection; the radio task never touches LVGL. Within 320×240 and the persistent bar show advertisement rate per observed second, coverage, loss and a scrollable list sorted by valid RSSI then address/type. Show age; expire entries five minutes after last sighting or on configuration change. Three missed expected revisits show `no-data`, gaps show `gap`, disabled shows `Operator disabled`, never zero. Detail shows address/type, RSSI or unavailable, decoded label and `Related Alerts: None yet` until TB14/15 exist.

## Acceptance and physical checks

TB11 owns `firmware/domain/tests/ble_observation_tests.cpp` and `firmware/domain/tests/hci_advertising_tests.cpp`; register `firmware_domain_ble_observation_tests` and `firmware_domain_hci_advertising_tests` under `./dev check firmware`. Register `./dev run simulator -- ble-observation` with the scenario source and expected file above. These commands and files are deliverables. Required fixtures and expectations:

- `ble-multi-report`: one complete HCI packet with three reports emits three ordered events; three identical reports count three, not one.
- `ble-address-types`: same six bytes public and random create two entries; random high bits 00/01/10/11 yield non-resolvable/resolvable/reserved/static; reserved and public add zero churn sightings, the other three random types qualify.
- `ble-ad-boundaries`: valid empty directed report counts one; truncated HCI or malformed AD counts zero for flood and churn; zero terminator ends parsing; five valid UUIDs retain four, flag overflow and count one report. RSSI 127 displays unavailable.
- `ble-signatures`: positive iBeacon, Eddystone UID/URL/TLM and Find My-pattern examples and wrong-prefix, wrong-company and one-byte-short near matches produce only the specified labels.
- `ble-window-loss`: planned 205 ms with 102 ms observed yields zero accepted events; 103 ms yields eligible events. Missing report yields zero. A 65th staged event, VHCI buffer overflow, or pre-deadline report processed after closure marks uncertainty and prevents recovery, including when no reports remain. Packet overflow count is never presented as exact report loss. Generation change discards unmatched old events and precedes new-generation acceptance; only a clean zero-drop window can advance quiet.

Append to TB09's shared physical session: compare a known advertiser and a second sniffer, verify address decoding and repeated reports, and test powered with no Host. Under the combined TB10 worksheet's declared loads for 10 minutes require each stage ≤5 ms/window, internal heap ≥20 KiB, radio/HCI stack margins ≥1 KiB, touch ≤150 ms, no unexplained reset or report loss; any observed loss must be attributed or uncertain and prevent quiet. Confirm no scan requests and 1 Hz Host cards when connected. Record build, port, commands, captures, measurements and pass/fail under `docs/evidence/TB11/` (created by implementation). Physical gate and TB09 Done are required for completion and dispatch respectively.
