# R02 — Fetch a verified release and recover USB firmware updates

- **Kind:** Release tracer bullet
- **Detail:** Outline
- **Status:** Not started
- **Milestones:** M7
- **Depends on:** [TB08](TB08.md), [TB16](TB16.md)
- **Board:** Exclusive flash and ROM-recovery sessions

Read [dispatch and completion rules](README.md#dispatch-and-completion). Refine this outline against prerequisite evidence before dispatch; it is not yet executable.

## Outcome

An explicit release fetch verifies artifacts, and a separate explicit action flashes firmware; interrupted or unbootable updates remain recoverable through BOOT/RESET.

## Proposed ownership

Own signed manifest/compatibility verification, explicit GitHub release client, updater/bootloader adapters, setup/CLI update views, and update fixtures. Coordinate shared version metadata with R01.

## Scope

Implement independent component compatibility, pinned trust material, checksums, bounded downloads and redirects, separate fetch/install actions, single-slot verified USB flashing, running-version verification, and ROM recovery documentation.

## Resolve before promotion

Define signing-key custody/rotation, manifest schema, compatibility selection, failure/rollback policy, flash partition preservation, and daemon serial-port handoff. Test fixture keys must remain distinct from release credentials; production signing evidence is required before qualification.

## Acceptance outline

- Normal monitoring makes no background network requests; fetch does not authorize install/flash.
- Invalid signature/hash/incompatible manifests are rejected before writing.
- Calibration/configuration/history partitions are preserved according to declared migration rules.
- Interrupted writes and an unbootable image can be restored through the ROM loader with documented manual actions.
- Successful flashing verifies the running version, not merely transferred bytes.

## Verification to specify

Use manifest/client/updater failure fixtures, explicit-network behavior checks, and physical successful/interrupted/unbootable-image recovery runs. Record exact fixture/scenario names, commands, and evidence paths when promoting this ticket.
