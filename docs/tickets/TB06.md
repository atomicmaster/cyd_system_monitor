# TB06 — Display battery charge and condition without blocking collection

- **Kind:** Tracer bullet
- **Detail:** Outline
- **Status:** Not started
- **Milestones:** M3, M4
- **Depends on:** [C02](C02.md)
- **Board:** Exclusive final display smoke; Mac battery optional

Read [dispatch and completion rules](README.md#dispatch-and-completion). Refine this outline against prerequisite evidence before dispatch; it is not yet executable.

## Outcome

The System detail shows battery state or explicit absence, while slow condition collection remains isolated from one-second Host updates.

## Proposed ownership

Own macOS battery adapters, bounded `system_profiler` parsing, battery fixtures, and `firmware/ui/system/battery/`. Consume C02 registration; TB03 owns RAM.

## Scope

Implement the public charge/state source and best-effort slow condition source with individual sample ages, deadlines, and failure states. Keep a fixture for batteryless hosts even if the development Mac has a battery.

## Resolve before promotion

Define subprocess timeout/output-size bounds, defensive parser fixtures, field units, and widget allocation within the System detail.

## Acceptance outline

- Batteryless hosts show absent, never zero charge.
- A hung or malformed slow source cannot stall complete snapshots.
- Source age, unsupported fields, charging state changes, and errors survive transport and display.

## Verification to specify

Use Host source/parser fixtures, System replay, and physical battery/absence display smoke. Record exact fixture/scenario names, commands, and evidence paths when promoting this ticket.
