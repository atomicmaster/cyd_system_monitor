## Outcome

The Network card shows primary-route and per-interface traffic, while WiFi identity/coverage is explicit about available, outside-band, and unknown context.

## Proposed ownership

Own Host network collectors and coverage mapping, network fixtures, and `firmware/ui/network/`. TB08 owns foreground permission UX and the signed-app provider; consume its agreed IPC interface without requiring permission for ordinary rates.

## Scope

Implement interface counter baselines, tunnel/underlying separation, Host Station Identity and link state, and available band/channel/BSSID context. Keep the CPU path usable when context is absent or denied. Exercise [Host metrics](../host-metrics.md) and [radio coverage](../radio-model.md).

## Resolve before promotion

Agree provider IPC with TB08 before parallel dispatch; use a fixture adapter until the real provider integrates. Verify actual platform availability/permission behavior and define identity freshness. Dependency on TB08 is an integration gate for the permission-granted scenario, not for core network work.

## Acceptance outline

- Tunnel and underlying traffic are never summed; route/identity changes reset rate baselines.
- 5/6 GHz is outside supported capture, unknown is explicit, and matching SSID alone cannot establish Host-targeted evidence.
- All Association Context Availability states have fixtures; TB08/R03 retain the real consent-path integration check.

## Verification to specify

Use network counter/route fixtures, provider IPC fixtures, coverage replay, and real supported-Mac observation. Identify granted/denied permission integration evidence shared with TB08. Record exact fixture/scenario names, commands, and evidence paths when promoting this ticket.
