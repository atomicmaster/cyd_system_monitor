## Outcome

The Network card shows primary-route traffic, and WiFi identity/coverage is explicit about available, outside supported band, and unknown context, without requiring permission for ordinary rates.

## Design (as built)

- **Wire:** group key 9 "Network", 13 required fields in two independent halves (traffic and WiFi context, each with its own availability and source age), at most 98 bytes; every field, sentinel and rule is in [CORE_PROTOCOL.md](../../protocol/CORE_PROTOCOL.md#metric-groups-c02). The snapshot body key limit rose from 9 to 10.
- **Traffic:** only the primary route's interface. A tunnel primary route reports the tunnel's own rate with `via_tunnel`, never summed with the link beneath. Rates are unavailable (never zero) on the first sample, counter decrease, bad clock, long gap, and route, interface or WiFi-station change. Counters come from `net.link.generic.ifdata` (64-bit); `NET_RT_IFLIST2` was measured on macOS 26 to return byte counts truncated to 32 bits in 1 KiB steps.
- **WiFi context:** Host Station Identity from `getifaddrs` without any permission; band/channel/SSID/BSSID only through the provider seam defined in [wifi-context-provider.md](../wifi-context-provider.md). 5/6 GHz is outside supported coverage, unknown is explicit, and a matching SSID alone never establishes Host-targeted evidence.
- **Device:** freshness derived from ages (traffic stale at 3 s, WiFi context at 15 s). Card `Network`: value `D1.2M U340K`, note such as `WiFi ch6 2.4GHz`, `VPN WiFi ch6 2.4G`, `WiFi 5/6GHz: no capture`, `WiFi context ?`, `Ethernet`, `Offline`; no bar.
- Skipped: a count of other active interfaces (it added a field without a display use).
