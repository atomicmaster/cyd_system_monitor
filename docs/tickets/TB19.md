# TB19 — Check and install agent activity hooks from the Host

- **Kind:** Tracer bullet
- **Detail:** Executable
- **Status:** Host implementation done; Remaining below. No board needed for the Host checks.
- **Milestones:** M3, M4
- **Depends on:** [TB07](TB07.md), [TB08](TB08.md)
- **Board:** None for the Host checks; a final display smoke if the device shows hook state

Read [dispatch and completion rules](README.md#dispatch-and-completion).

## Outcome

The Host can say, for each supported agent, whether its activity hooks are installed and point at this `cyd-host`. A still mascot can then be told apart from "hooks missing". The Operator installs or removes them with one command. Adding a future agent's hooks is one table entry, not new plumbing.

## Background

Busy and idle come only from each agent's own hooks calling `cyd-host agent-event <agent> busy|idle` ([agent integrations](../agent-integrations.md#busy-and-idle-activity-events-every-agent)); there is no CPU fallback. Today the hooks are written by hand into each agent's config (Claude Code `~/.claude/settings.json`, Codex `~/.codex/hooks.json`). An agent whose hooks are missing, partial, or point at a moved or rebuilt binary silently reads `running, activity unknown`, and nothing tells the Operator why.

## Proposed ownership

A pure hook-adapter table and config checker in `host/metrics` (or a new `host/agent-hooks` crate), the `cyd-host hooks` CLI, the hook state in `cyd-host status` and the TB08 setup status, and fixtures of each agent's config format. Coordinate any wire or device change (showing hook state on the expanded Agents screen) with the contract owner.

## Scope

- **One adapter table.** Each entry: the agent slug, its config file(s) (home-relative), the format (Claude `settings.json` hooks, Codex `hooks.json` or inline `[[hooks.EVENT]]` in `config.toml`, later others), and the event→`busy`/`idle` map already documented per agent. A new agent is a new entry plus its config fixture.
- **Check** (`cyd-host hooks status`, and part of `cyd-host status`): per agent `installed`, `partial` (some events missing), `outdated` (a `cyd-host agent-event` entry that points at another or a missing binary), `not installed`, `agent not installed`, or `config unreadable`. Codex keeps hook trust as `hooks.state."<file>:<event>:<group>:<handler>".trusted_hash` in `~/.codex/config.toml`; its app server reports each hook's `trustStatus` and `currentHash` (`hooks/list`) and records trust with `config/batchWrite` on `hooks.state`, the same calls its `/hooks` screen makes. On the development Mac the Codex hooks were trusted that way (a stdio JSON-RPC session with `codex app-server`), so the check can report trust and the installer can grant it after Operator consent, without reimplementing Codex's hash. Where an agent keeps trust out of reach, say `trust unknown` rather than guess. It reads only the hook sections of those config files, never other keys, sessions, logs or credentials.
- **Install / remove** (`cyd-host hooks install|remove [agent…]`): merge or delete only entries this tool owns (recognised by their `agent-event <slug>` command), keep every other hook (for example herdr's and tldraw's), back up the file first, write atomically, and be idempotent. Point at the installed `cyd-host` (the TB08 service location), not a build directory.
- **Optional:** a periodic Host check that reports hook drift (for example after the binary moves), and a device-side note on the expanded Agents screen.

## Resolve before promotion

Where the installed `cyd-host` lives once TB08/R01 fix the install layout (today the hooks point at `host/target/release/cyd-host` in this checkout). Whether the R01 installer runs `hooks install` with consent or leaves it to the Operator. How to handle a JSON config with comments or an unknown schema version (refuse and report, never rewrite). Whether hook state goes on the wire.

## Acceptance outline

- Fixture tests for every adapter's config: installed, partial, outdated path, foreign hooks only, malformed file, and missing file each give the right state.
- Install then remove leaves a config byte-for-byte equal to the original apart from formatting the tool documents; a second install changes nothing; foreign hooks survive both.
- `cyd-host status` names each agent's hook state; a still mascot with `not installed` is explained in the docs and status output.
- No read outside the listed config files; no hook payload is read (`agent-event` keeps draining stdin unread).

## As built

`cyd-host hooks status|install|remove [agent...]` lives in `host/cli/src/hooks/` with no new crate dependency.

- **`json.rs`:** a strict RFC 8259 reader and writer. Objects keep key order, numbers keep their source text, output is two-space indented with a final newline. It refuses comments, trailing commas, duplicate keys (at any level), a byte order mark, text over 1 MiB and nesting over 32 deep; the caller reports `config unreadable` and never rewrites.
- **`adapters.rs` (pure):** the table `ADAPTERS`, one entry per agent (config directory, config file, format, event→busy/idle map exactly as in [agent integrations](../agent-integrations.md)). Formats: JSON hooks under a key (`Shared`: Claude `settings.json` and Codex `hooks.json`, only our handlers are edited; `WholeFile`: Grok's `cyd-system-monitor.json`; `OwnKey`: Gemini's `cyd-activity` group), and the OpenCode plugin generated from `host/integrations/opencode/cyd-system-monitor.js` (embedded with `include_str!`, path JS-escaped). A hook is ours iff its command contains `agent-event <slug> `. Install re-points our handlers in place and adds a group for each missing event; remove drops only our handlers and prunes the groups, events and keys it emptied. Commands are `'<abs path>' agent-event <slug> <busy|idle> 2>/dev/null || true`, with `"timeout": 5` for Claude and Codex (Grok's and Gemini's documented examples have none).
- **`files.rs`:** the bounded read of the one listed file, the `<file>.bak-cyd-<YYYYMMDDHHMMSS>` backup (only when the file existed and changes), temp-file-and-rename writes that keep the original mode (new files `0644`), a symlinked config edited through its link, and parent directories created `0700` only below an agent config directory that already exists.
- **`codex.rs`:** `codex app-server` over stdio JSON-RPC (`initialize`, `initialized`, `hooks/list`, `config/batchWrite` on `hooks.state`) behind the trait `CodexRpc`, bounded to 15 s and killed afterwards; any failure reads `trust unknown (...)`. `status --trust` shows our hooks' trust; `install --trust` trusts only our own hook keys that are `untrusted` or `modified`.
- **`mod.rs`:** argument parsing and the commands. The binary is this executable's canonical path, or `--cyd-host <absolute path>`. States per agent: `installed`, `partial`, `outdated` (our hook pointing elsewhere, at a missing binary, or reporting the wrong state), `not installed`, `agent not installed` (no config directory), `config unreadable`. `status` exits 0 always; with `--check`, 1 unless every agent is `installed` or `agent not installed`. `install` and `remove` take `--dry-run`, exit 1 if any agent failed, and are idempotent.

Privacy: only each agent's one listed config file is read or written; no session, log, history or credential, and `agent-event` still drains stdin unread.

Adding an agent is one `ADAPTERS` entry and the fixtures `host/cli/fixtures/hooks/<slug>.foreign.<ext>` (a realistic config with other people's hooks) and `<slug>.installed.<ext>` (its install result, regenerated with `UPDATE_FIXTURES=1 cargo test -p cli` and reviewed); the table-driven tests fail for an entry without them.

## Acceptance, as tested

All tests are in `host/cli/src/hooks/` (`cargo test -p cli`), on a temporary fake home, never the real one.

- **Every adapter's states** (installed, partial, outdated path or missing binary, foreign hooks only, malformed, missing file): `tests::a_status_of_every_kind_for_every_json_adapter`, `tests::every_adapter_has_a_config_fixture_and_round_trips_through_it`; in `adapters::tests`: `install_into_nothing_is_installed_for_every_adapter`, `missing_file_is_not_installed`, `a_missing_event_is_partial`, `another_path_or_a_missing_binary_is_outdated`, `a_wrong_state_is_outdated`, `foreign_hooks_only_is_not_installed`, `malformed_or_unexpected_configs_are_unreadable`, `plugin_states`; the event maps: `event_maps_match_the_documented_ones`.
- **Install then remove restores the file; a second install changes nothing; foreign hooks survive:** `adapters::tests::install_keeps_foreign_hooks_and_settings_and_remove_restores_the_file`, `a_second_install_changes_nothing`, `an_installed_file_in_another_format_is_not_reformatted`, `gemini_owns_only_its_group`, `grok_file_is_replaced_wholesale`; end to end `tests::install_all_then_status_all_then_remove_all_in_a_fake_home` (no backup and no change on the second install).
- **Refuse, never rewrite:** `adapters::tests::unreadable_configs_are_never_rewritten`, `plugin_install_and_remove_refuse_a_foreign_file`, `tests::unreadable_configs_are_reported_and_left_untouched`, `json::tests::strict_rfc_8259_only`, `comments_are_named_in_the_reason`, `duplicate_keys_are_refused_at_any_level`.
- **The JSON module:** `json::tests` (round trip, unicode escapes and surrogates, numbers kept as text, depth and size limits, key order).
- **Writes:** backup, mode, atomic write, `0700` parents only under an existing config directory, symlinks, UTC stamp: `files::tests`; `--dry-run` writes nothing: `tests::a_dry_run_changes_nothing`; no directory for an agent that is not installed: `tests::a_missing_agent_directory_is_not_an_error`.
- **Status output and exit:** `tests::status_exit_follows_check`, `tests::a_real_binary_makes_status_installed`, `tests::arguments_are_validated`, `tests::the_binary_path_is_checked`, and `tests::usage_mentions_every_command` in `main.rs`.
- **Codex trust:** `codex::tests::only_our_untrusted_or_modified_hooks_need_a_grant`, `trust_is_described_for_our_hooks_only`, `a_hooks_list_reply_is_read`, the app-server exchange against a fake `codex` script (`the_app_server_exchange_lists_and_grants`), the 15 s bound and kill (`a_silent_codex_times_out_and_is_killed`), failures (`errors_exits_and_a_missing_program_are_reported_not_raised`); `tests::codex_trust_is_shown_only_when_asked_and_granted_only_for_ours`, `codex_trust_failures_read_as_unknown_and_never_fail_the_install`.
- **No read outside the listed files:** `tests::nothing_but_the_listed_files_is_read`; `agent-event` is unchanged.
