# C01 — Define and exercise the first USB snapshot contract

- **Kind:** Contract foundation
- **Detail:** Executable
- **Status:** Done — contract commits `953931c` and `1a59bbb` (base `f86c2e0`); see [Handoff](#handoff).
- **Milestones:** M2
- **Depends on:** [F08](F08.md)
- **Board:** None; uses F08 measurements

Read [dispatch and completion rules](README.md#dispatch-and-completion) before starting. Command names below are planned deliverables, not tools that already exist.

## Outcome

C++ and Rust agree on bounded bytes for negotiation, pairing, time, and one complete CPU snapshot before either runtime builds its own interpretation.

## Ownership and inputs

Own `protocol/` product schema/specification, golden vectors, generator configuration, decoder, `firmware/protocol/`, and `host/crates/protocol/`. Consume F04 tooling and F08 serial/RAM limits. Other tickets consume generated types; handwritten shared-schema changes remain with this contract owner.

## Work

1. Specify length framing, integrity check, limits, stream resynchronization, optional-field behavior, and malformed-input errors. Decide limits from F08 evidence rather than unbounded containers.
2. Cover supported/incompatible versions, random persistent identities, matching-code pairing, session identity/sequences, bounded commands including unpair/calibration reset, configuration revision exchange, and UTC/source uncertainty.
3. Define the complete CPU snapshot, value units, per-field sample age, availability, freshness, and capability semantics. Omitted unimplemented capabilities are not zero-valued metrics.
4. Generate types and independent expected byte fixtures; exercise both codecs, stream fragmentation, bad lengths/checksums, duplicate/stale-session messages, and unknown optional fields. Keep Host business logic and firmware domain logic out of the schema generator.

## Acceptance

- Both codecs accept the same valid vectors and reject the same bounded invalid cases; generated files reproduce exactly.
- Examples define idempotent command replies and session reset behavior without incremental metric updates.
- Negotiation fails visibly and safely for incompatible majors; the device can still expose incoming/supported versions.
- The decoder makes bytes inspectable. Maximum first-slice messages fit F08's envelope; a mismatch reopens that budget before consumers proceed.

## Verification and handoff

Run `./dev check protocol`, `./dev check host`, `./dev check firmware`, and `./dev run protocol -- decode <fixture-path>`. Publish the fixture names, byte limits, schema revision, ownership map, and contract commit. C01 does not claim live pairing or full MVP protocol completion; TB02 proves live operation, and later slices add their contracts before their consumers.

## Handoff

- **Contract:** [protocol/CORE_PROTOCOL.md](../../protocol/CORE_PROTOCOL.md), protocol major 1 minor 0; codecs in `protocol/core/cpp/` (firmware) and `host/protocol/` (Host).
- **Limits:** frame 2,048 bytes (length field ≤ 2,046); non-snapshot body 512 bytes; unknown-value skip ≤ 16 items, < 4 deep, no tags/floats; sequences are u32 and monotonic per session. The 2,048 cap replaces an initial 1,024: F08's estimate of a full 12-metric snapshot is ~1,019 CBOR bytes, so 1,024 could not hold it plus session identity and framing. At 1 Hz that is about 2 KB/s against F08's measured ~9 KB/s ceiling. The full snapshot's interface list must still be capped (F08 suggests 8) when its fields are added.
- **Fixtures (`protocol/fixtures/`, 24 hex vectors):** golden `cpu-snapshot-v1`, `hello-v1`, `hello-reply-v1`, `pair-v1`, `command-v1`, `command-reply-v1`, `error-v1`; rejected: bad-crc, incompatible-major (CPU and Hello), noncanonical, duplicate-key, missing-body, tag, too-deep, zero-length, trailing-byte, truncated, oversized-length, five-digit pairing code, wrong-body Hello; accepted forward-compatibility: unknown-optional, unknown-nested, large-unknown (~1.2 KB). `parity-matrix.txt` and `session-parity-matrix.txt` are run by both codecs.
- **Ownership:** schema, fixtures, generator and both codecs stay with the contract owner; consumers do not hand-edit generated types. Regenerate vectors with `protocol/tools/gen_vectors.py`.
- **Verification run:** `./dev check protocol`, `./dev check host`, `./dev check firmware` pass; `./dev run protocol -- decode <fixture>` inspects any vector.
- **Not claimed:** live pairing and the full MVP field list (TB02 and C02). Pair/command bodies remain minimal, and the CPU snapshot is the only concrete snapshot body.
