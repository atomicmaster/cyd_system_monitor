# TB10 — Observe WiFi traffic through to an inspectable view

- **Kind:** Tracer bullet
- **Detail:** Outline
- **Status:** Not started
- **Milestones:** M5, M4
- **Depends on:** [TB09](TB09.md)
- **Board:** Exclusive radio/display smoke

Read [dispatch and completion rules](README.md#dispatch-and-completion). Refine this outline against prerequisite evidence before dispatch; it is not yet executable.

## Outcome

Observed 2.4 GHz WiFi evidence becomes bounded BSS/activity/transmitter summaries on the display, with associated coverage context.

## Proposed ownership

Own WiFi frame parsing/aggregation modules, WiFi evidence fixtures, and `firmware/ui/wifi/`. Consume TB09 events and C02 domain interfaces; scheduler code remains with TB09.

## Scope

Implement BSSID identity, safe SSID rendering, management/control/data frame summaries, frame rates, estimated observed airtime, and transmitter detail without retaining raw payloads. Supply deauthentication/disassociation evidence for TB12.

## Resolve before promotion

Define supported frame metadata, malformed/truncated-frame handling, bounded label/identity cardinality, airtime assumptions, and per-window rate normalization. Record limits against F08 memory budgets.

## Acceptance outline

- Same SSID does not merge BSSID identities or establish physical owners.
- Rates/airtime refer to received evidence in known windows, not total congestion.
- Malformed and hostile-volume input remains bounded and gaps remain visible.
- WiFi UI and CPU path work together on the board.

## Verification to specify

Use parser/evidence fixtures, WiFi replay, and a physical known-BSS observation with measured coverage. Record exact fixture/scenario names, commands, and evidence paths when promoting this ticket.
